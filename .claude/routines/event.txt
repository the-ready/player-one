このファイルは `.claude/scripts/claude-routine.sh`（cronから起動される）が読み込む、週次データ収集の実行手順である。

## 前提 —— git 操作はスクリプトが行う

- **git の pull / add / commit / push を、この手順の中で実行してはならない。** すべてスクリプト側の責任に移してある。
  これはお願いではなく、`PreToolUse` フック（`.claude/hooks/block-git.sh`）が実際に拒否する。
  読み取り（`git status` / `log` / `diff`）は通るので、状態の確認には使ってよい
  - 実行前: スクリプトが `git fetch` と fast-forward マージで最新を取り込んでから、あなたを起動している
  - 実行後: スクリプトが `validate_data.py` と `diff_data.py` を回し、**どちらも終了コード0のときだけ** コミットして push する
- 検証に通らなかった回は、スクリプトが生成物を `.claude/logs/failed/` に退避したうえで `data/` と `docs/` を実行前の状態に戻す。つまり**途中で終えた週は、その週の収集がまるごと失われる。**
- したがってあなたの仕事は、**「検証を通る状態のCSVを作り、終了工程まで通し切ること」** に尽きる。

## 手順

1. 実行日の曜日を確認し、実行するスキルを1つ決める。
   - 水曜日 → `kanto-live-collector`
   - 木曜日 → `kanto-movie-collector`
   - 金曜日 → `kanto-event-collector`
   - それ以外の曜日 → テスト実行の可能性が高い。ユーザから特段の指示がなければ `kanto-event-collector` を実行する

   **手順書は `.claude/skills/<スキル名>/SKILL.md` を Read で直接読むこと。`/kanto-...` のスラッシュコマンドで呼び出さない。**
   同じ名前のコピーが `~/.claude/skills/` にもあり、こちらは手動同期なので古いことがある
   （実際に、書き出し先を `data/events.csv` ではなく**ルート直下の `events.csv`** と書いた版が残っていた）。
   名前で呼ぶとどちらが読まれるかが実行環境に依存するので、リポジトリ内の正本をパスで指定して読む。
2. 選んだスキルを、SKILL.md の「実行手順まとめ」の**最後の項目まで**実行する。
   - 調査（探索・深掘り）は、予算切れ・コンテキスト逼迫・情報源への到達失敗などを理由に**打ち切ってよい**
   - ただし SKILL.md の「完走条件」にある**終了工程は、どんな理由で打ち切っても必ず全部通す**。終了工程はローカルのコマンドだけで完結し、Web検索を1回も使わないので、予算が尽きていても必ず実行できる
   - 打ち切る場合は SKILL.md の「撤退の手順」に従い、未処理の前回行を持ち越しまたは `notfound` として片付けてから終了工程に入る

   **時間は6時間ある。** 撤退を判断する前に `python3 tools/budget.py --report` で残りを見ること。
   正常に完走した回は5時間27分を使っており、何も産まずに終わった回は18分で終わっている。
   **まだ余っているのに畳まないこと。**

   **サブエージェントを使ってよい。ただし背景では起動しない。**
   - `run_in_background: false` を明示する（**書かないと既定で背景起動になり、フックが拒否する**）
   - **全ての結果を `append_rows.py` で書き終えるまで、ターンを終えない**
   - サブエージェントは調査だけを行い、`data/` には書かない。結果は JSONL で親に返す
   - worktree 隔離は使わない（書き込まないので隔離する対象が無く、名簿の更新まで破棄される）
   - **1回の呼び出しに、調査軸1つの全体を背負わせない。** 名簿の一部・対象期間の一部などに区切り、**波**（同時に起動して同時に受け取る1組）に分けて呼ぶ
   - **1つの波の結果を全部 `append_rows.py` で書き切ってから、次の波を投げる。** 波をまたいで投げ続けない
   - **1波の体数は自分で数えなくてよい。** `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` が、その日のスキルに応じた上限をこのスクリプトから渡している（live 3体・movie 2体・event 3体）。超えた起動は失敗する。**孫エージェントは禁止**（`settings.json` の `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`）

   以前、4地域の調査を背景のサブエージェントに委ね、親が先にターンを終えたことがある。
   バックグラウンドは600秒で打ち切られ、**4体ぶんの調査結果が誰にも受け取られないまま
   破棄された**（検索115回・取得154回を消費して、新規0件）。禁止しているのはこの形だけで、
   並行して調べること自体は推奨する。

   2026-08-20 の movies 収集は、前景起動を守っていても同じ壊れ方をした。3軸それぞれの
   全体（85館・6ヶ月分）を1回の呼び出しに丸ごと背負わせ、3体分の結果をまとめて受け取ってから
   `append_rows.py` で書く設計にしていたところ、開始12分後にアカウントの利用上限
   （`session limit`）で3体とも打ち切られ、`--init` 以降 `append_rows.py` への追記が一度も
   ないまま終わった。前回123件のほぼ全件が「説明のない消滅」として検出され、`Stop` フックが
   差し戻している（本番データへの実害はない）。**背景起動の禁止だけでは、1回の呼び出しが
   長時間に及ぶ設計までは守れない。** 区切るのは起動の形だけでなく、1回に背負う範囲でもある
   （`docs/COLLECTION-PROTOCOL.md` 第11.3節）。

3. `data` ディレクトリ配下の該当CSVが更新されていることを確認する。**ヘッダーだけの状態（`--init` した直後の状態）で終わらせない。**
4. `python3 tools/diff_data.py` と `python3 tools/validate_data.py` を実行し、どちらも終了コード0であることを確認する。
   落ちた場合はその原因を解消してから終える。ここが通らないと、今回の成果は保存されない。
   - **説明のない消滅**があると落ちる → `tools/prev_rows.py <events|lives|movies> --dispose` で理由を記録する
   - **収穫が0件**（新規・変更・消滅がすべて0）でも落ちる → 調査結果を `append_rows.py` で
     書き切っていないか、前回のCSVをそのまま復元して終えようとしている。
     **前回分を復元して「検証が通る状態に戻しました」で終えるのは、完走ではない。**
5. `python3 tools/report_stats.py` で充足率と分布を出す。
6. 最後に、SKILL.md が求める報告を出力して終了する。次の3つは必ず含める。
   - `python3 tools/report_stats.py` の出力（件数・**中核列の充足率と前回比**）
   - `python3 tools/budget.py --report --verbose` の出力（工程別の消費・残り時間）
   - 打ち切った工程がある場合は、**どの工程をどの理由で打ち切ったか**
