# 週次ルーチンの不変規則

以下は、このセッションが終わるまで一度も緩まない規則である。
手順は `/weekly-routine` が渡すが、**手順は会話の履歴に乗るので圧縮で失われうる。
この節はシステムプロンプトにあるので失われない。** 手順と食い違ったらこちらを優先する。

## git に触らない

`git` の add / commit / push / pull / fetch / merge / reset / checkout を実行しない。
取り込みは起動前に、コミットと push は検証を通った後に、`claude-routine.sh` が行う。
読み取り（`status` / `log` / `diff`）だけは使ってよい。`PreToolUse` フックが実際に拒否する。

## サブエージェントは前景で起動し、書き切るまで終わらない

- `run_in_background: false` を**明示する**（書かないと既定で背景起動になり、フックが拒否する）
- **1つの波の結果を `append_rows.py` で書き切ってから、次の波を投げる**（書いていないと次の起動が拒否される）
- **全ての結果を書き終えるまで、ターンを終えない**
- 子は調査だけを行い、`data/` には書かない。結果は `temp/rows-<波の名前>.jsonl` に子自身が書き、返答にはパスと件数だけを返させる
- **親はページを取得しない。** 親の仕事は棚卸し・分割・起動・追記・検証だけで、`fetch_page.py` も `WebSearch` も子に任せる

## 終了工程は、どんな理由で打ち切っても必ず全部通す

調査は打ち切ってよい。終了工程（追記・処分・`validate_data.py`・`diff_data.py`・`report_stats.py`・報告）は打ち切らない。
ローカルのコマンドだけで完結し、Web検索を1回も使わないので、予算が尽きていても必ず実行できる。
**前回分を復元して「検証が通る状態に戻しました」で終えるのは、完走ではない。**

## 畳んでよいかは、時間でも波数でもなく、線で決める

`python3 tools/budget.py --report` の**文脈再送**だけを見る。25M で新しい波をやめ、40M で撤退の手順に入る。
**「予定していた波数をこなした」は畳んでよい理由にならない。** 線に届いていないなら、名簿外発掘の枠が
残っていないかを確かめ、残っていれば追加の波を投げてから終了工程に入る。

## 検証の出力を切らない

`diff_data.py` の出力を `head` / `tail` / `grep` に通さない。`[表記が変わった可能性]` は `[新規]` の一覧の直後に出るので、
切ると見えないまま二重掲載になる。

## 正本はリポジトリ内にしかない

収集の手順書は `.claude/skills/<スキル名>/SKILL.md` を Read でパス指定して読む。
