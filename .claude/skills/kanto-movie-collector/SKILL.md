# 関東映画収集タスク（週次）

## このタスクの目的

`data/movies.csv` を更新し、ダッシュボード「イベントボード」の「映画」タブに**今週から6ヶ月以内に観に行ける上映**を並べること。

新作ロードショーだけではない。名画座・ミニシアターのリバイバル上映、夏季の野外上映やドライブインシアター、爆音上映・オールナイトなどの特別上映、映画祭まで含めて「新作映画や、復活上映の映画の公開日や期間」を利用者が一目で把握できるようにすることがゴールである。

`/kanto-event-collector` と同じ思想（**実際に確認できた情報だけを書く。不明なら空欄にする**）をそのまま踏襲する。特に料金・上映期間については、確認していないものを推測で埋めることを固く禁止する。

## 取得してよいもの・いけないもの（着手前に読むこと）

このタスクは cron から週次で自動実行される。**「人が調べているのと同じ」ではなく機械的なアクセスである。**

1. **`robots.txt` が `Allow` している範囲だけを取得する。** サイト単位ではなく**URL単位**で見る
2. **収集後に拒否の意思が示されたと分かったサイトは、由来する行を消し、`data/sources.json` からも外す**
3. **利用規約で自動収集・データの二次利用を明示的に禁じているサイトは使わない**
4. **会員登録・ログインが要る領域には立ち入らない**（無料会員でも同じ）
5. **同じホストへ続けて当たらない**（待つのは `fetch_gate.py` の仕事で、自分で数える必要はない）
6. **1サイトあたりの取得は、その週の調査に要る分だけ**

**判断に迷ったら取らない。** 1と2が礼儀ではなく著作権法47条の5の政令基準に対応すること、
3を別項にしてあるのは30条の4が契約を上書きしないためであること、判定に
`Claude-User` と `Claude-SearchBot` の厳しいほうを採る理由——これらは
**`docs/COLLECTION-PROTOCOL.md` 第6.5節に全部書いてある。判断に迷ったらそこを読む。**

### 着手前：使えないサイトを一望する（検索予算を消費しない）

```bash
python3 tools/check_robots.py                  # data/sources.json の調査元サイト
python3 tools/fetch_gate.py --roster theaters   # 名簿のURL（この工程の主な取得先）
```

どちらも robots.txt だけを見る軽い確認なので、**検索予算を消費しない**。拒否と出たURLは今回の収集から外す。

### 取得のたび：URLごとに判定し、間隔を空ける（自動で走る）

**サイトのトップが「OK」でも、これから開くページが `Allow` されているとは限らない。**
`tools/fetch_gate.py` が `PreToolUse` フックに登録してあり、**`WebFetch` のたびに自動で走る**。

- **拒否されたURLはブロックされる。** 別ページを当たるか、その行を落とす。**回避しようとしないこと**
- **許可されたURLは、必要な待ち時間を消化してから通る。** 自分で数えて待つ必要はない
- **「次の取得まで N 秒必要」と断られたら、先に別のホストを回る**（`Crawl-delay: 120` のサイトが実在する）

```bash
python3 tools/fetch_gate.py --check <URL>   # 判定だけ（待たない・記録しない）
```

> **`curl` でページ本体を取りに行かないこと。** ゲートを迂回することになる。
> ページの内容が要るときは `python3 tools/fetch_page.py <URL> --text` を使う——
> **ゲートを通したうえで本文だけを取る正規の手段**である（下記「検索を使わずに済ませる」）。

> **拒否されている先でも、許可された経路があることがある。** connpass は
> `Disallow: /` だが `Allow: /*.ics` を併記しており、
> `https://connpass.com/event/{id}.ics` は取得してよい（`fetch_page.py --ics` で読める）。
> **「このサイトは拒否」で止めず、robots.txt が何を開けているかを見ること**
> （`docs/COLLECTION-PROTOCOL.md` 第6.5.8節）。

## 完走条件 —— このタスクをどう終えるか（着手前に読むこと）

**このタスクは「調べ終わったとき」ではなく、終了工程を通したときに終わる。**

検索の予算が尽きた、コンテキストが逼迫したなどで**調査を途中で止めざるを得なくなったとき**の正しい振る舞いは、「そこで終わる」ことではなく、**探索をやめて下の撤退の手順に入り、終了工程まで通し切る**ことである。

### 終了工程（省略不可）

| #   | やること                                           | コマンド                                      |
| --- | -------------------------------------------------- | --------------------------------------------- |
| 1   | 手元に残っている調査済みの行を書き切る             | `python3 tools/append_rows.py movies`         |
| 2   | 終了日を過ぎた行を機械的に取り除く                 | `python3 tools/purge_ended.py movies`         |
| 3   | 消えた行（2で片付いた分以外）1件ずつに理由を付ける | `python3 tools/prev_rows.py movies --dispose` |
| 4   | 名簿を整理する                                     | `python3 tools/roster.py theaters --gc`       |
| 5   | 差分を確定する（終了コード0）                      | `python3 tools/diff_data.py movies`           |
| 6   | 検証する（ERROR 0）                                | `python3 tools/validate_data.py`              |
| 7   | 充足率と分布を出す                                 | `python3 tools/report_stats.py movies`        |
| 8   | 報告を出力する                                     | ——                                            |

**この8つはすべてローカルのコマンドで、Web検索を1回も使わない。** つまり**検索の予算が尽きていても、コンテキストが逼迫していても、終了工程は必ず実行できる**。「予算が尽きたので終わります」という終わり方に、正当な理由は存在しない。

> **2 は「まだ確認できていない行」の保険であって、1・3の代わりではない。** 映画は終映日が告知されないまま静かに終わることが多く、tier A の再確認が検索予算切れで間に合わなかった行は、上映が終わった後もそのまま持ち越されがちである——表示側は上映終了日から毎回「上映終了」を計算して既定の一覧から隠す（設計書 第5.4.1節）ので利用者の目には触れないが、CSVの中には残り続ける。`purge_ended.py` は「終了日（`end_date`）が今日より前か」という一点だけを機械的に見て、そういう行をここで刈り取る。判断が要らないぶん `--dispose` より先に置いてあり、消した行には `expired` という処分が自動で付くので、3 で個別に扱う必要はない。**確認できた行を `ended` として `--dispose` するほうが、この自動処理より常に望ましい。** `expired` は「確認できないまま終了日だけが過ぎた」という、確認不足のしるしだからである。**新作ロードショー（`end_date` が未定のまま上映中の行）はこの機械判定の対象外**——上映終了は日付ではなく劇場の判断で決まるため、収集タスクが公式情報で確認するしかない。

### やってはいけない終わり方

- ❌ `--init` した後、追記が途中のまま終える（**ダッシュボードに残るのは書けた分だけ**になる）
- ❌ 調査結果をコンテキストに溜めたまま終える（追記していない行は、最初から無かったのと同じ）
- ❌ `diff_data.py` / `validate_data.py` を通さずに終える
- ❌ 「予算が尽きたのでここまでにします」と述べて、終了工程を飛ばす
- ❌ 報告を出さずに終える

> **`--init` は `data/movies.csv` を空にする。** そこから終了工程を通すまでの間、CSVは未完成の状態にある。**着手したら、必ず終了工程まで通し切ること。**
>
> 自動実行のスクリプト（`.claude/scripts/claude-routine.sh`）は、`diff_data.py` と `validate_data.py` が通らなかった回をコミットせず、`data/` を実行前の状態に戻す。**途中で終えた週は、その週の収集がまるごと失われる。**

### 撤退の手順 —— 打ち切りは「中断」ではなく「終了工程へ進むこと」

調査は打ち切ってよい。次のどれかに当たったら、**その場で探索をやめて**下の手順に入る。

- 工程ごとの枠（「調査予算」）を使い切った
- 検索の**合計が150回**に達した（枠の合計170回のうち、20回を余裕として残す）
- コンテキストが逼迫してきた
- 情報源に到達できない状態が続く（取得の失敗が連続する）

1. 調査済みで未追記の行を `append_rows.py` で書き切る
2. `python3 tools/purge_ended.py movies` を通す（終了日を過ぎた行を先に機械的に片付ける。3の対象を減らせる）
3. `python3 tools/diff_data.py movies --allow-unexplained --allow-noop` で、まだ処理していない前回行を出す
4. 残った行を片付ける（**ここから先は検索を使わない**）
   - まだ上映が続いていると判断できる行 → `python3 tools/prev_rows.py movies --uid <uid>` で前回値を引き、そのまま書き戻す（tier C の持ち越し。`status`/`rank` は表示側が日付から計算するので触らなくてよい。**`onsale_*` は空欄にする**）
   - 判断できない行 → `--dispose` に `notfound` として記録する
5. 終了工程の 4〜8 を通す
6. 報告に「どの工程を、どの理由で打ち切ったか」「持ち越した行数」「`notfound` の件数」「上映劇場を特定できずに落とした作品の件数」を書く

### 進捗はツールが出す（自分で書かなくてよい）

`append_rows.py` が追記のたびに、次の1行を標準エラーへ出す。自動実行のログに残り、
**途中で止まったときに「どこまで進んだか」を人間が判別できる唯一の手がかり**になる。

```
[進捗] 追記8件（累計34件）/ 検索 63/170（残り107） / 取得 154（うち拒否2） / 待機 12分 / 経過 96分/360分（残り264分）
```

工程名を添えたいときは、工程の切り替わりで `python3 tools/budget.py --phase "<工程名>"` を打っておく。

## 出力仕様

### 出力先

- **`data/movies.csv` のみ**（全件を毎回書き直す。追記ではなく完全再生成）。`index.html` はこのタスクでは編集しない
- ダッシュボードは `data/movies.csv` を Web サーバー経由で取得する前提で作られており、`file://` で直接開く運用は想定していない

> **書き出し先に注意**: ダッシュボードは `data/` 配下しか読まず、別パスへのフォールバックを意図的に持たない。リポジトリのルート直下に `movies.csv` を書いても反映されず、古い表示が残る。

- `data/theaters.csv`（映画館の名簿）も `tools/roster.py` 経由で更新する。**SKILL.md（この文書）の目標件数・品質基準・禁止事項は自分で書き換えない。** 名簿（データ）は自動更新、それらは提案止まりという線を守り、変更提案は `docs/skill-feedback.md` に書く。**それに当たらない小さなバグ**（誤字脱字、壊れたコマンド例、古いパス・URLの参照、`tools/*.py` の些末な不具合など）は、この SKILL.md・`tools/`・対応する設計文書の記述を自分で直してよい。直した内容は `docs/skill-feedback.md` の「自己修正ログ」に記録すること。線引きは `docs/COLLECTION-PROTOCOL.md` 第7.1節

### 出力方法（CSV書き出しの手順）

全件を最後にまとめてCSVに書くのではなく、調査の区切りごとにバッチで追記する。**全件を調査結果としてコンテキストに溜め込んでから最後に一括生成する、という進め方はしないこと。**

1. 調査開始前に `python3 tools/append_rows.py movies --init` を実行し、`data/movies.csv` をヘッダーだけの状態にする。**このとき前回の内容は `data/.prev/` に自動退避される**（差分検知の材料になる）
2. 5〜10件の調査が完了するごとに、結果をまとめて以下の形式でCSVに追記する

   ```bash
   python3 tools/append_rows.py movies <<'EOF'
   {"title": "...", "genre": "...", "theater": "...", ...}
   {"title": "...", "genre": "...", "theater": "...", ...}
   EOF
   ```

3. コンテキストに全件のデータを保持する必要はない。追記が終わったバッチの内容は忘れてよい（次の調査のためにコンテキストを空ける）
4. `id` はスクリプトが自動採番する。JSONに含める必要はない
5. JSONに含めない列は空文字で補完される。分かっている列だけを渡せばよい
6. 全件の調査・追記が終わったら `python3 tools/diff_data.py movies` と `python3 tools/validate_data.py` を実行する

自然なバッチの区切りの例：

- 公開予定カレンダーで1ヶ月分の新作を拾ったらまとめて書く
- 名画座・ミニシアターの定点観測リストを調べたらまとめて書く
- 調査ステップが変わる節目（新作調査→名画座調査→野外上映補完）でまとめて書く

#### 前回から変わっていない列は書き直さない（持ち越し）

劇場の座標・読み・劇場URLは、前回値から自動で補完される。**空欄のまま渡してよい。**

内容にも変更がないことを**確認できた**行は、`"_carry": "*"` を添えると `desc` `note` `official_url` なども前回値で埋まる。

```bash
python3 tools/append_rows.py movies <<'EOF'
{"title": "...", "release_date": "2026-07-31", "screening_type": "new", "genre": "anime",
 "theater": "TOHOシネマズ|109シネマズ", "area": "東京都・千代田区", "pref": "tokyo",
 "price": "一般2,000円",
 "source": "eiga.com", "url": "https://...", "_carry": "*"}
EOF
```

> **公開日・料金・前売り期間は持ち越せない。** `onsale_end` や `price_best` を `_carry` に指定するとスクリプトがエラーで落ちる。**ムビチケの販売終了日は公開日に向かって迫ってくる**ので、前回値の流用は「終わった前売りを発売中に見せる」ことになる。

| `start_time`      | 上映開始時刻 `H:MM`。無ければ空欄                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `end_time`        | 終了時刻 `H:MM`。無ければ空欄                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `date_note`       | 上のどれにも収まらない但し書き（例：`オールナイト` `土日祝のみ` `1週間限定` `毎朝10時開始`）。**日付や時刻そのものをここに書き写さない**——構造化列に入れれば画面が組み立てる                                                                                                                                                                                                                                                                                                |
| `backup_date`     | **予備日**（雨天・荒天で順延したときの日）を `\|` 区切りで。**会期には含めない**——本開催で終わればこの日は使われないので、`end_date` を1日延ばすと「まだやっている」と嘘をつくことになる。カードの日付欄ではなく「くわしく」の中に出る。**予備日の当日は「本日予備日」バッジが出る**ので、順延が実際に起きたら開始日・終了日を新しい日に書き換えてこの列を空にすること                                                                                                      |
| `date`            | **原則として空欄。** ISOの日付に落とすと持っていない精度を騙ることになる日程（`2026年10月中旬〜下旬（見頃予想）` `8月の毎週土日` など）だけ、ここに自由記述で書く。**書いた行はこの文字列がそのまま表示され、上の構造化列は使われない**。**ただし月・季節までは読み取れる場合、`release_date`/`end_date` にはその月・季節をまるごと設定すること**（下記「幅のある予測日程」参照）——空欄のままだと日程の絞り込みが「無期限」として扱い、無関係な日で絞っても表示されてしまう |
| `status` / `rank` | **原則として空欄。** 日付から毎回計算される。開始日も `end_date` も持たない行——つまり `date` に自由記述を書いた行——でだけ、下の表から選んで書く                                                                                                                                                                                                                                                                                                                             |

**なぜ表示用の文字列を書かないのか。** 以前は `date` に表示用の文字列を、`status` に
収集した日の判定を書いていた。書き手ごとに表記がそろわず（同じ会期が `2026.8.1〜9.30` にも
`2026年8月1日〜9月30日` にもなる）、しかも**収集した日で時間が止まる**——週の後半に見た人には、
始まっているものが「まもなく開催」のまま残る。どちらも「計算できる値を、計算せずに書き置いた」
ことが原因である。**書いた値が画面に出ないのは気持ちが悪いかもしれないが、書かないほうが正しい**
（設計書 第3.9節）。

##### 幅のある予測日程（「10月中旬〜下旬」「2026年夏」など）は、`date` だけでなく `release_date`/`end_date` も埋める

`date` に自由記述を書く行のうち、**月・季節までは読み取れる**ものは、`release_date`/`end_date` を
空欄のままにしてはいけない。空欄は「本当に何も分からない」の意味になり、**日程の絞り込みが
一切効かなくなる**——10月開催のイベントが8月の日付で絞っても一覧に出てしまう。
読み取れた月・季節を**まるごと**設定する（精度は落ちるが、誤って除外するより実害が小さい。第3.9.6節）。

| 読み取れた期間 | `release_date` | `end_date`   |
| -------------- | -------------- | ------------ |
| 10月中旬〜下旬 | `2026-10-01`   | `2026-10-31` |
| 2026年夏       | `2026-06-01`   | `2026-08-31` |

`date` 列の表示はそのままでよい。埋めた行は `status`/`rank` を空欄に戻すこと。
**月すら読み取れない行**（「会期は公式サイト参照」）は両方空欄のままにする——
読み取れる情報が無いところに月を割り当てるのは、それこそ憶測になる。

`python3 tools/validate_data.py` は、`date` に「◯月」「春」「夏」「秋」「冬」を含む自由記述があるのに
`release_date`/`end_date` が両方空の行を WARNING で挙げる。出たら必ずこの手順に従うこと。

### 前売り券（`onsale_*`）の書き方

映画の「受付期間」は前売り券の販売期間にあたる。書くと、カード表面に「前売り発売中／前売り発売前／前売り終了」と締切カウントダウンが出て、「前売りが買えるものだけ」で絞り込めるようになる。

| 列                                   | 規則                                                                                                           |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `onsale_label`                       | 券種（例：`ムビチケ前売券（カード）` `オンライン前売券`）。売り切れ・終了なら `販売終了` `SOLD OUT`            |
| `onsale_start` / `onsale_start_time` | 販売開始日 `YYYY-MM-DD` と時刻 `HH:MM`                                                                         |
| `onsale_end` / `onsale_end_time`     | 販売終了日と時刻。**多くのムビチケは公開日の前日で販売を終える**が、作品ごとに違うので必ず販売ページで確認する |
| `limited_sale`                       | 特典付き前売り・数量限定券など（例：`特典付き 限定5,000枚`）。無ければ空欄                                     |

**時刻が書かれていないときは空欄にする。** 画面側は「開始時刻が空なら0:00、締切時刻が空なら23:59」として扱う。勝手に補うと、その時刻まで「発売前」と嘘をつくことになる。

### 料金（`price_official` 〜 `price_condition`）—— 条件を書けない割引は載せない

映画料金は「同じ席を安く買う」経路が多く、イベントと同じ形で比較できる。ただし**映画の割引はほとんどが条件付き**である点がイベントと決定的に違う。

| 列                | 規則                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------- |
| `price_official`  | 通常料金（一般1名・円・数値のみ）。例：`2000`                                               |
| `price_best`      | 実際に払える最安額（一般1名・円・数値のみ）。例：`1300`                                     |
| `discount_pct`    | 割引率（整数%）。**両方揃った時のみ**。値引き額から計算した値と2%以上ずれると検証で落ちる   |
| `best_source`     | 最安を提供している経路名。例：`ムビチケ前売券` `auマンデー` `イオンシネマ ハッピーマンデー` |
| `coupon_note`     | 配布中クーポンの説明                                                                        |
| `price_checked`   | 価格を確認した日 `YYYY-MM-DD`。**価格を1つでも書いたら必須**                                |
| `price_condition` | **適用条件。条件付きの割引を書いたら必須**                                                  |

**`price_condition` の絶対規則。**

- `au/UQ mobile会員・月曜のみ` / `毎月1日` / `20:00以降の上映回` / `会員登録が必要` / `60歳以上` のように、**誰が・いつ・どうすれば**その額になるのかを書く
- 条件が特定できない割引は、**書かずに落とす**。条件を伏せた安い価格は、値段を出さないより有害になる（「1,300円だと思って行ったら2,000円だった」を作る）
- 誰でも無条件に買える前売り券（ムビチケ一般1,500円など）は、条件が「公開前に買うこと」だけなので `公開日前日までの購入` と書く
- **レディースデイ等、特定の性別・属性を条件とする割引は載せない。** 適用できない人には無関係な情報で、そのために表示スペースを割く意味がない

### `theater` 列の書き方（重要）

新作ロードショーで特定の1館だけを書くと、「そこでしか観られない」という誤解を与える。**上映形態によって書き方を変える**こと。ダッシュボード側は、新作(チェーン名)の行は場所を表示せず**チェーン名のみ**表示し、名画座・野外上映・特別上映・映画祭の行は具体的な会場名を表示する仕様になっている。この表示仕様と矛盾しないように、以下の書き方を厳守する。

| `screening_type`                    | `theater` に書く内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `new`（新作・全国/広域公開）        | **上映しているシネコンチェーン名**を書く（例：`TOHOシネマズ` `109シネマズ` `イオンシネマ` `ユナイテッド・シネマ` `MOVIX` `T・ジョイ` `USシネマ` `ヒューマントラストシネマ`）。特定の1館名（例：`TOHOシネマズ日比谷`）は書かない。**複数チェーンで同時公開されている場合は `\|` 区切りで複数書いてよい**（例：`TOHOシネマズ\|109シネマズ\|イオンシネマ`）。チェーン名の表記は下記「チェーン名の表記統一」のリストの表記に厳密に合わせること（ダッシュボードが `theaters.csv` の店舗ディレクトリと突き合わせて店舗地図を表示する際、表記が一致していないと機能しないため） |
| `new`（単館・limited公開）          | その作品を上映しているのが本当に1館だけ（単館系ミニシアター限定公開など）と確認できた場合に限り、その具体的な劇場名を書く                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `revival`（名画座・リバイバル）     | 具体的な劇場名を書く（例：`新文芸坐` `早稲田松竹`）。その劇場でしか観られない一回性の企画のため                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `outdoor`（野外上映・ドライブイン） | 具体的な会場名・臨時会場名を書く                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `special`（特別上映）               | 具体的な劇場名を書く（爆音上映・オールナイト・舞台挨拶付きは特定の劇場・日時に紐づく一回性の企画のため）                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `festival`（映画祭）                | 具体的な会場名を書く                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

`area`・`lat`/`lng` は `theater` の書き方に関わらず、代表的な上映劇場（新作なら関東での主要上映館の1つ。複数チェーンの場合はいずれか1つでよい）の座標を入れてよい。座標は地図検索・現在地検索のために必要なので、チェーン名を書く場合でも省略しない（**ダッシュボードは新作行の`area`をカード上のテキストとしては表示しないが、地図検索・県フィルタの内部処理では引き続き使うため、空欄にしないこと**）。

#### チェーン名の表記統一（`theaters.csv` と一致させる）

映画チェーンの店舗ディレクトリは `data/theaters.csv` に別途まとめてある（`chain,name,pref,area,lat,lng,url` に加えて、名簿の保守用に `status,first_seen,last_hit,hit_count,note` を持つ）。新作行の `theater` に書くチェーン名は、必ず `theaters.csv` の `chain` 列に実在する値と**完全に一致**させること（表記ゆれがあると、チェーン名をクリックしたときの店舗地図が空になる）。対象チェーンは概ね以下の通り：

```
TOHOシネマズ / イオンシネマ / 109シネマズ / MOVIX / ユナイテッド・シネマ / T・ジョイ / USシネマ / ヒューマントラストシネマ
```

`theaters.csv` に載っていない新しいチェーン名を使う場合は、`python3 tools/roster.py theaters --add` で名簿に追加したうえで、収集結果の報告にもその旨を書くこと（チェーン名の表記が名簿と一致していないと、店舗地図が空になる）。

## 収集ルール

### 1. 対象期間は「直近6ヶ月のみ」

実行日から6ヶ月後までに**公開・上映されている、または公開・上映が始まる**作品のみを対象とする。

- ✅ 実行日時点で上映中のもの（新作ロードショーは終了日未定でも可）
- ✅ 6ヶ月以内に公開・上映が始まるもの
- ❌ 6ヶ月より先にしか公開・上映されないもの → **含めない**
- ❌ すでに上映が終了したもの → **含めない**

### 2. 対象地域は関東1都6県

東京都・神奈川県・埼玉県・千葉県・茨城県・栃木県・群馬県。

### 3. 目標件数

`revival`・`outdoor`・`special`・`festival` は合計で**20〜40件**を目安とする（5つの上映形態のうち `new` 以外の4種すべてから最低3件は拾うこと。ジャンルも8割が邦画実写・アニメに偏らないよう、洋画・ドキュメンタリー・特撮なども探すこと）。

**`new`（新作）には上限を設けない。** 「ステップ1：新作ロードショーの網羅調査」で拾えた対象期間内の新作は、目標件数を理由に間引かず全件載せる。結果として全体の総件数が70件を超えても構わない（件数より網羅性を優先する）。

各都県から最低2〜3件は拾い、東京に偏りすぎないようにすること（東京は全体の半分程度まで）。

## 調査予算 —— 検索は有限である（着手前に読むこと）

**Web検索の呼び出しは、1セッション200回で打ち切られる。**

**このスキルは特に上限に当たりやすい。** 公開予定の一覧サイトには対象月だけで120件超が載ることがあり、それを「新作は全件拾う」と解釈して1件ずつ裏取りすると、**上限に達して、公開日だけ分かって上映劇場・公式URLを確認できなかった作品を丸ごと落とすことになる**。

つまりこのスキルでは、**予算の配り方がそのまま収録件数を決める**。「たくさん調べる」ことは品質ではない。

```bash
python3 tools/roster.py theaters --list --urls | awk -F'\t' '$2==""'   # 名画座・単館だけ
```

2列目が `chain`（空欄なら名画座・単館）。**ステップ2で回るのは名画座・単館だけでよい**——シネコン店舗は新作の上映館であって、独自の特集上映を組む先ではないためである。名画座・単館だけなら取得はその件数で済み、**検索はステップ2の枠5回**——名簿に足したばかりでURLが無い劇場のぶんだけである。

前回から続いている作品も同じで、**前回の `official_url` を引けば検索は要らない。**

### 同じことを二度調べない —— 打ち切りの基準

**必須列が揃った行は、そこで調査を終える。**

| 区分                           | 列                                                                                                               | 扱い                                                                                                                                                                |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **これが揃ったら終わり**       | `title` `genre` `screening_type` `area` `theater` `pref` `release_date`/`end_date` `price` `source` `url` `desc` | 揃った時点で次の行へ移る                                                                                                                                            |
| **ついでに拾うだけ**           | `kana` `note` `theater_url` `series_id` `announced_date` `is_additional`                                         | 開いたページに書いてあれば書く。**このために追加でページを開かない**                                                                                                |
| **調べない（臨時会場を除く）** | `lat` / `lng`                                                                                                    | `theaters.csv` と前回値から自動で補完される。**空欄で渡す**。ただし名簿にも前回にも無い臨時会場（野外上映・ドライブイン）は、その会場のページを開いたついでに埋める |

**具体的にやってはいけないこと**

- ❌ シネコンチェーンの店舗を1館ずつ検索して、同じ新作の上映情報を何度も確認する（`theater` にはチェーン名を書くので、**店舗ごとの確認は不要**）
- ❌ 新作の公開日を、カレンダーサイトで確認した後に配給会社サイトでも確認し直す（食い違いに気づいたときだけ当たり直す）
- ❌ ポスターやキービジュアルの画像URLを探す（**CSVに画像の列が無い**。探す工程そのものが存在しない）
- ❌ `kana` や `series_id` が分からないので検索する（分からなければ空欄が正しい）
- ❌ 料金の割引条件を特定するために検索を重ねる（条件を書けない割引は**価格ごと落とす**のがこのスキルの規則である）

### 「新作は全件」の現実的な線引き

「新作には上限を設けない」という方針は維持する。ただし**予算の中で全件を拾うために、深掘りの対象を絞る。**

- ✅ **シネコンチェーンで公開される作品、または上映劇場が具体的に確認できる作品** → 全件拾う。これが「全件」の対象である
- ⚠️ **単館系ドキュメンタリー・自主制作・海外インディーズで、上映劇場を特定できない作品** → カレンダーで公開日を確認した段階で、**1回調べて劇場が分からなければ落とす**。`url` は必須列なので、どのみち収録できない
- ❌ **1作品のために3回以上検索する** → その予算で、確認できる作品を3件収録するほうが利用者に資する

**予算を薄く広く配ると、「日付だけ確認できて劇場を確認しきれない作品」が多数残り、どの作品も収録できないまま終わる。**

### 予算が尽きたら、何を捨てるか

上から守り、**下から捨てる**。

1. **tier A の再確認**（映画は終映日が告知されずに静かに終わる。落とすと終わった作品が載り続ける）
2. **新作の網羅**（カレンダーの確認。落とすと話題作を落とす）
3. **公開前の新作の前売り**（`onsale_*`。下記「今週かならず産む成果」）
4. 新規行の深掘り
5. 名画座・野外・特別上映の探索
6. **補助列（`kana` `note` `series_id`）の穴埋め** ← 最初に捨てるのはここ

> **`onsale_*` を 6 から 3 に移してある。** 補助列と同じ扱いにしていた結果、
> 実測では130件すべてが空欄（0%）だった。前売りは「あれば書く」ものではなく、
> **利用者が公開前に行動できる唯一の情報**である（`price_*` と違い、
> 公開日が来れば取り返しがつかない）。

**目標件数に届かないことより、未検証の行を足すことのほうが重い失敗である。** 打ち切ったら、その事実と工程名を報告に書く。

### 今週かならず産む成果（下限）

**捨てる順を決めるだけでは、何も産まない週を止められない。** 下限を決めておく。

| 成果                     | 下限                                                                         | 確認のしかた                               |
| ------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------ |
| **公開前の新作の前売り** | `release_date` が実行日より後の `new` 行について、**前売りの有無を確認する** | `report_stats.py` の `onsale_label` 充足率 |
| 新作の網羅               | 対象期間の全月のカレンダーを確認する                                         | 報告に確認した月を書く                     |
| 上映終了日               | 名画座・特集上映（`revival` `special` `festival`）は `end_date` 必須         | `report_stats.py` の `end_date` 充足率     |

**前売りは、作品公式サイトを開いた同じ取得の中で分かる。** 「チケット」「前売券」の
記載を見て、あれば券種と販売終了日を、無ければ**無いことを確認した**という意味で
`onsale_label` を空欄のまま次へ進む。**追加でページを開く必要はない**ので、
「予算が無いからできなかった」は成り立たない。

ムビチケの販売終了日は多くが公開日前日だが、**作品ごとに違うので必ず販売ページで確認する**
（推測で公開日前日と書かない。従来どおり、確認できないなら空欄）。

再確認まで手が回らなかった tier C の行は、**消さずに前回値のまま書き直してよい**（`prev_rows.py --uid` で全列を引ける）。ただし **`onsale_*` は空欄にする**（ムビチケの販売終了日は公開日に向かって迫ってくるので、前回値の流用は禁じられている）。詳細は `docs/COLLECTION-PROTOCOL.md` 第8.5節。使った行数は報告に含めること。

## 並行して調べてよい —— ただし親が待ち切ること

都県や名簿を分割して同時に調べるのは、予算配分として正しい。**縛るのは起動の形と、1回に背負う範囲**である。

- **背景で起動しない。** `run_in_background: false` を明示する
  （**書かないと既定で背景起動になり、`agent-guard.sh` が拒否する**）
- **親は、全ての結果を `append_rows.py` で書き終えるまでターンを終えない**
- サブエージェントは**調査のみ**。`data/` には書かず、結果は JSONL で親に返す
- **worktree 隔離を使わない**（書き込まないので隔離する対象が無く、名簿の更新まで破棄される）
- 分けるのは**取得先が重ならない軸**で（都県・名簿の種別）。「日程係」「料金係」に分けると同じページを2回開く
- **1回の呼び出しに、調査軸1つの全体を背負わせない。** 名簿の一部・対象期間の一部などに区切り、**波**——同時に起動して同時に受け取る1組——に分けて呼ぶ
- **1つの波の結果を全部 `append_rows.py` で書き切ってから、次の波を投げる。** 波をまたいで投げ続けない（打ち切られたとき、どこまで書けたか分からなくなる）
- **1波の体数は自分で数えなくてよい。** `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` が上限を与える（**このスキルは2体**。3スキルで最も少ない）。超えた起動は `Concurrent subagent limit reached` で失敗する

**このスキルだけ2体なのは、作品数ではなくホスト数の都合である。** `theaters.csv` は85館あるが、
チェーンの全店舗が同じホストに載っているのでホストは25しかない。さらにステップ1の新作カレンダーは
eiga.com 等の集約サイト数件に取得が集中する。体数を増やしても `fetch_gate.py` の待ち行列が伸びるだけで、
トークンだけが体数ぶん増える。**このスキルで並列化が効くのは、16ホストに分かれている名画座・単館（ステップ2）である。**

背景起動を禁じている理由——4体ぶんの調査結果が誰にも受け取られないまま破棄された実例——と、
前景でも1回の範囲が大きすぎると同じことが起きた実例（2026-08-20、movies）は
`docs/COLLECTION-PROTOCOL.md` 第11章にある。体数をホスト数から決めてある理由は第11.2節。

### サブエージェントへの指示に必ず含めること（省略禁止）

2026-08-21 に姉妹スキル（events）をHaikuで実行した実測では、指示にこれらが無かったために**15体中3体がJSONLを1件も返さず**（うち1体は再要請しても直らず8件が回復不能のまま失われた）、**会期が残っている前回行の大半を再発見できず**、補助列の充足率が**0%近くまで落ちた**。次の5項目は、都度書くのではなく**指示のテンプレートに固定で含める**こと。

1. **「返り値は JSONL そのもの。要約や件数の報告だけを返すのは失敗」と1文で明記する。** 書かなければ、モデルは「調査した内容の要約」を返して終わりがちで、機械可読な行が1件も戻ってこない
2. **担当範囲の前回行を渡す。** `python3 tools/prev_rows.py movies --worklist --pref <担当都県>` の出力をそのまま指示に含め、「この一覧の行を再確認しながら新規を探すこと」と明記する。前回分の照合をサブエージェント任せにすると、実行時には素通りされる
3. **このスキルの中核工程を名指しする**——**前売り（`onsale_*`）の有無確認**。「今週かならず産む成果」章にあるとおり、公開前の新作は前売りの有無を確認するのが下限の成果である
4. **「開いたページに書いてあれば拾う」補助列を列挙する**——`kana` `note` `series_id` `announced_date` `is_additional`。書かなければ0%のまま埋まらない
5. **有効なキーの一覧と対象期間を明記する。** `genre` は `anime` `jp-live` `foreign` `doc` `fam` `tokusatsu` `music` の7キー、`screening_type` は `new` `revival` `outdoor` `special` `festival` の5キーのみ（それ以外は `append_rows.py` が拒否する）。対象地域は関東1都6県、対象期間は実行日から6ヶ月以内に公開・上映が始まるもの・または実行日時点で上映中のもの

### 親の残りトークンが少ないときの追加指示（サブエージェントには意識させない）

タスク着手時点で、Claude Codeが示す残りトークン数（コンテキストの残量表示）を控えておく。**これは親（このタスクを実行している自分自身）だけが気にすればよく、サブエージェントに「自分の残りトークンを確認しながら進めて」と指示してはならない**——サブエージェント自身に残量を意識させると、調査そのものの遂行能力が落ちる。

以後、残りが着手時の**10%を切ったら**、その時点から新しく投げるサブエージェントの指示に次の一文を追加する。

> 担当範囲を最後までやり切れなくてよい。区切りのよいところ（1件・1都県などの単位）まで進めたら、そこまでの結果をJSONLで返してターンを終えてよい。

**強制的に打ち切らせるものではない。** すでに動いているサブエージェントに割り込むのではなく、次に投げる指示にあらかじめ「早めに畳んでよい許可」を含めておくことで、キリの悪いところで打ち切られる事故を防ぐための措置である。

> 差分検知・持ち越し・名簿更新の考え方は `docs/COLLECTION-PROTOCOL.md` に詳しい。手を動かすのに必要なコマンドはこのSKILL.mdに全部ある。

### ステップ0：前回分の棚卸し（省略禁止）

**新規の調査を始める前に、前回載せた上映の一覧を取る。**

```bash
python3 tools/prev_rows.py movies --worklist
```

前回分の全行が、CSV全文より1桁小さい圧縮一覧で出る（**CSV全文をそのまま読んではいけない**）。全列が必要になった行だけ、あとから引く。

```bash
python3 tools/prev_rows.py movies --uid 3f2a1b9c
python3 tools/prev_rows.py movies --venue 新文芸坐
```

```bash
python3 tools/prev_rows.py movies --worklist --tier A   # 今回必ず再確認する行だけに絞る
```

**一覧の先頭に「先週、確認できないまま消えた行」が出る。今週いちばん最初に確かめるのはここである。**

| 印         | 意味                                     | やること                                                              |
| ---------- | ---------------------------------------- | --------------------------------------------------------------------- |
| `notfound` | 先週、調べたが分からなかった行           | **まだ開催中なら「静かな欠落」になっている。** 会場ページで確かめ直す |
| `expired`  | 終了日を過ぎて機械的に消えた行（未確認） | **会期が延長されていた可能性がある。** その会場を開くついでに見る     |

これらの行は前回のCSVにはもう残っていない。**この一覧に出さない限り、二度と視界に入らない。**
拾い直せたら普通に行として書けばよく、本当に終わっていたなら何もしなくてよい。

映画は tier A（今回必ず再確認）の比率が高い。新作は公開日が動き、前売りは公開日で締まり、名画座の特集は1〜2週で入れ替わるためである。

tier の判定は3スキル共通で、`tools/prev_rows.py` が機械的に付ける。

| tier  | 意味                                                                                                                       |
| ----- | -------------------------------------------------------------------------------------------------------------------------- |
| **A** | 今回必ず再確認する（**公開日・終了日が10日以内**／**前売りの締切・発売が21日以内**／`onsale_label` があるのに締切が空 等） |
| **B** | 劇場ページを開いたついでに確認する（**価格の確認日が45日より古い行**もここ）                                               |
| **C** | 低頻度でよい（日程を持たない行）                                                                                           |

**tier は「手を抜いてよい行」を決めるためのものではなく、限られたページ取得の回数を
変わりやすい行から先に使うための優先順位である**（`docs/COLLECTION-PROTOCOL.md` 第3.1節）。

この工程で確認するのは、次の4つ。

| 確認すること                              | 見落とすとどうなるか                                                                   |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| **まだ上映しているか**                    | 終わった作品が「上映中」として残る。映画は終映日が告知されないことが多く、静かに終わる |
| **上映が延長されたか**（`is_additional`） | アンコール上映・ロングラン継続を拾えない                                               |
| **前売りが終わっていないか**              | 買えない前売りを「発売中」として見せる                                                 |
| **上映館が増減していないか**              | 拡大公開・縮小をカードに反映できない                                                   |

> **新作行の `theater`（チェーン名）が変わっても、同じ作品として扱われる。** 差分の同定に新作の会場は使っていないため、「翌週に109シネマズが加わった」場合は [消滅]+[新規] ではなく [変更] として出る。

### ステップ1：新作ロードショーの網羅調査（最重要・省略禁止）

**新作（`screening_type=new`）は「取りこぼしなく全件拾う」ことを最優先とする。** 個別のシネコンを1館ずつ検索して見つかったものだけを載せる、というやり方は取りこぼしの原因になるため行わない。必ず**公開予定を一覧できるカレンダー・リストのページ**を起点にすること。

1. **公開予定カレンダーを月ごとに確認する。** 実行日を含む月から6ヶ月後までの各月について、以下のようなページを開き、**掲載されている作品を全部**書き出す（大作・話題作に限らず、小規模公開の作品も含めて拾う）。
   ```
   {実行年}年{実行月}月 公開映画 一覧
   {実行年}年{実行月+1}月 公開映画 一覧
   {実行年}年{実行月+2}月 公開映画 一覧
   {実行年}年{実行月+3}月 公開映画 一覧
   ```
   eiga.com・映画.com・シネマトゥデイ・Yahoo!映画などの「公開予定」「新作映画」一覧ページ、Wikipediaの「{年}年の映画」記事なども横断的に使う。
2. **主要配給会社ごとの公開予定ページも確認する。** カレンダー系サイトは掲載漏れや配給会社発表前の情報を拾えないことがあるため、東宝・東映・松竹・ワーナー ブラザース ジャパン・ディズニー（日本語）・ソニー・ピクチャーズ・ユニバーサル・ギャガ・KADOKAWA・アスミック・エース・ロングライド・ショウゲート・松竹ODS等の「公開予定作品」ページを確認する。
3. **1で拾った作品ごとに**、公開日・上映しているシネコンチェーン（`theater`列の書き方は前章の表に従う）・料金を個別に確認する。**1作品あたりの検索は原則1回**とし、**3回以上使わない**（「『新作は全件』の現実的な線引き」参照）。上映劇場を特定できない単館作品は、その1回で分からなければ落とす。
4. **話題作・大作を取りこぼしていないか最後に必ずセルフチェックする。** 実行時点で世間的に注目されている大作・続編・話題のアニメ映画等が対象期間内にあるにもかかわらず一覧に入っていない、という状態が起きていないかを確認すること。**「目標件数に達したから打ち切る」という理由で新作の掘り起こしを止めない。** 新作は目標件数の上限にかかわらず、対象期間内に公開されるとわかっているものは可能な限り全件載せる。

> **この工程は単価が安い。** 1ページのカレンダーから何十件も取れるので、**枠20回のうち大半は1・2（一覧ページと配給会社ページ）に使い、3の個別確認はステップ4の枠で行う**。逆に、シネコンの店舗を1館ずつ当たるのは最も単価が高く、しかも `theater` にはチェーン名しか書かないので**得るものがない**。

### ステップ2：名画座・ミニシアターの特集上映調査

定点観測する劇場は `data/theaters.csv` にある。

```bash
python3 tools/roster.py theaters --list --pref tokyo --urls
python3 tools/roster.py theaters --list --urls | awk -F'\t' '$2==""'   # 名画座・単館だけ
```

**4列目に劇場の公式サイトURLが出る（全件埋まっている）。この工程では、そのURLを直接開く（検索しない）。検索の枠は5回。**

**回るのは名画座・単館（2列目の `chain` が空欄の16件）だけでよい。** シネコン店舗は新作の上映館であって、独自の特集上映を組む先ではない。新作は `theater` にチェーン名を書く仕様なので、店舗ごとに調べても書ける情報が増えない。

**1館につき1回、上映スケジュールを調べる。そのとき「前回分の照合」と「新規の発見」を同時に済ませる。** 名画座の特集は1〜2週で入れ替わるので、前回の行はほぼ入れ替わっているはずだが、**入れ替わったことを確認せずに落としてはいけない**（延長されている場合がある）。

```
{劇場名} 上映スケジュール {実行年}年{実行月}月
{劇場名} 特集上映
```

収穫があった劇場、閉館した劇場、新しく見つけた劇場は、その場で名簿に反映する。ミニシアターは閉館・開館が多い。

```bash
python3 tools/roster.py theaters --retire ○○シネマ --reason "2026年5月閉館"
python3 tools/roster.py theaters --block ○○シネマ --reason "robots.txt が拒否"  # 閉館ではない
python3 tools/roster.py theaters --add <<'EOF'
{"chain": "", "name": "○○座", "pref": "tokyo", "area": "東京都・中野区",
 "lat": "35.70", "lng": "139.66", "url": "https://..."}
EOF
```

`chain` はシネコンチェーンの店舗なら親チェーン名、名画座・単館なら空欄にする（`theaters.csv` はチェーンの店舗ディレクトリと名画座の名簿を兼ねている）。**収集元のページの文言を `note` にそのまま持ち込まないこと**（`roster.py` が指示文めいた文字列を拒否するが、そもそも入れない）。

### ステップ3：野外上映・ドライブインシアター・特別上映の補完調査

施設リストに載らない単発の上映イベントを、季節キーワードと横断サイトで補完する。

```
関東 野外上映 {実行年}年{実行月}月
ドライブインシアター 関東 {実行年}
{映画タイトル} 爆音上映
{映画タイトル} オールナイト上映
映画祭 関東 {実行年}
```

補完用の横断サイト：eiga.com / 映画.com / Filmarks / シネマトゥデイ / ぴあ映画生活 / Yahoo!映画

### ステップ4：各作品・上映の深掘り

**この工程の枠は80回**（「調査予算」参照）。**枠を使ってよいのは新規行だけ**である。前回から続く行は、前回の `official_url` を直接開けば検索は要らない。

拾った作品・上映1件ごとに、**公式サイトや劇場公式サイトまで辿って**以下を確定させる。まとめサイトの記載だけで済ませない（日付・料金が古いことがある）。

1. **正確な公開日・上映期間**
2. **何が目玉か** — あらすじではなく、特集の切り口・上映形態の特徴（二本立て、爆音、日時指定制など）
3. **料金** — 券種ごとの正確な金額
4. **公式サイトURL・劇場URL**

**1〜4は、原則として作品公式サイト1回の取得で揃う。** 項目ごとにページを開き直さないこと。

#### 深掘りを打ち切る基準

**必須列（`title` `genre` `screening_type` `area` `theater` `pref` `release_date`/`end_date` `price` `source` `url` `desc`）が揃った時点で、その行の調査を終える。**

- **料金は「一般◯◯円」が確認できれば十分**である。割引の適用条件を特定するために検索を重ねない——**条件を書けない割引は価格ごと落とす**のがこのスキルの規則なので、掘っても書けない
- **新作の `theater` はチェーン名でよい**。どの店舗で何時から上映しているかは、このCSVに書く列が無い

前回から続いている上映については、**変わりうる項目（上映継続の有無・上映館・前売りの締切）だけ**を確認すればよい。目玉・座標を毎回調べ直す必要はない（`_carry` で持ち越す）。

### ステップ5：消えた行の説明と、差分の確定

まず、終了日を過ぎたのに再確認が間に合わなかった行を機械的に片付ける。

```bash
python3 tools/purge_ended.py movies
```

検索を使わない機械的な処理で、消した行には自動で `expired` の処分が付く（`end_date` が未定のまま上映中の新作は対象外——上映終了は劇場の判断で決まるので、機械には判定できない）。**この工程を通しても、確認できた行を `ended` として `--dispose` する手間はそのまま残る**。

次に、**前回にあって今回に無い行**（`purge_ended.py` で片付いた分を除く）を片付ける。

```bash
python3 tools/diff_data.py movies --allow-unexplained --allow-noop
```

「消滅」として挙がった行は、必ず次のどちらかである。

1. 上映が終わった／公開が延期・中止になった → 正しく消えている
2. 今回は確認できなかった → **上映中の作品を一覧から落とした事故**

**映画は終映日が告知されないまま静かに終わることが多い**ので、「消えたから終わったのだろう」という推測が特に通りやすい。だからこそ1件ずつ確認して記録する。

```bash
python3 tools/prev_rows.py movies --dispose <<'EOF'
{"uid": "3f2a1b9c", "status": "ended",        "note": "劇場の上映スケジュールから外れたことを確認"}
{"uid": "8d7e6f50", "status": "cancelled",    "note": "公開延期（配給発表）"}
{"uid": "a1b2c3d4", "status": "out-of-scope", "note": "公開が6ヶ月より先に延びた"}
{"uid": "b2c3d4e5", "status": "notfound",     "note": "上映館を特定できず"}
EOF
```

最後に名簿を整理し、差分と検証を確定させる。

```bash
python3 tools/roster.py theaters --gc
python3 tools/diff_data.py movies       # 説明漏れがあると落ちる
python3 tools/validate_data.py          # ERROR 0 を確認
```

`diff_data.py` の出力が、そのまま報告の「前回からの変化」になる。**記憶や印象で変化を書かないこと。**

## 画像は扱わない（このタスクで特に注意すること）

> **`data/movies.csv` に画像の列は存在しない。ポスター・スチール・キービジュアルのURLを、どの列にも書いてはならない。**

3タブとも画像を扱わない。権利者が出しているのは自社サイトへ掲載するための許諾であって、第三者サイトへの再掲載や画像への直リンクの許諾ではないためである。画像ファイルを複製せずURL参照するだけでも、サイトの利用規約違反と著作者人格権（氏名表示権）の問題は残る。判断の詳細は `docs/DESIGN.md` 第7.1節。

**このルールは `tools/validate_data.py` が検証する。** `poster_url` / `poster_source` の列を復活させた時点で ERROR になり、週次ルーチンのコミットが止まる。作品情報を読みに開いたページのOGP画像を拾うのは常に最も安い経路であり、散文のお願いは安い経路の前では負けるので、仕組みで担保してある（第7.1節）。

**画像を探す工程そのものが無いので、そのぶんの調査予算は他に使ってよい。** ステップ4で作品公式サイトを開いたときも、OGP画像やキービジュアルを見に行かないこと。

## `desc` の書き方

100〜150字程度で、**その上映の何が特別なのかを具体的に**書く。

### 悪い例（一般論・中身なし）

> ❌ 話題の新作映画です。ぜひご覧ください。
> ❌ 名作を大きなスクリーンで楽しめます。

### 良い例（目玉が具体的）

> ✅ 一週間限定の二本立て特集で、監督デビュー作と最新作を続けて上映。トークイベントは初日のみ、要事前予約。
> ✅ 屋外駐車場を使ったドライブインシアター企画。車内から鑑賞するため冷房いらずで、荒天時は中止・順延の判断が当日17時に告知される。

### 含めるべき要素

- **目玉**（特集の切り口、上映形態の特徴、規模感）
- **注意事項**（日時指定制、事前予約必須、雨天中止など）

### 含めないもの

- 配給会社の宣伝文句をそのまま転記したもの
- 「必見」「感動」といった評価語
- 出典サイトの文章のコピー（**必ず自分の言葉で書き直す**）

## 実行手順まとめ

> **手順8〜13は終了工程である**（終了工程表の1「調査済みの行を書き切る」は、手順7の追記をやり切ることに当たる）**。調査を途中で打ち切る場合も、ここは必ず全部通すこと**（「完走条件」参照）。終了工程はローカルのコマンドだけで完結するので、検索の予算が尽きていても実行できる。

0. **`python3 tools/check_robots.py` と `python3 tools/fetch_gate.py --roster theaters` を実行し、調査元サイトと名簿URLの robots.txt を確認する**（検索予算は消費しない。拒否されたURLは対象から外す。個々のページの可否は、取得のたびにフックが自動で判定する）。あわせて「調査予算」の工程別の枠を確認し、`python3 tools/budget.py --report` で今回の消費と**残り時間（上限6時間）**を見る（**このスキルは特に上限に当たりやすい**）
1. 実行日を確認し、対象期間（実行日 〜 6ヶ月後）を確定する
2. `python3 tools/append_rows.py movies --init`（前回分は `data/.prev/` に自動退避される。**先に `--init` してから棚卸しを取ること**——先週の `carried.jsonl` が今回分に更新されるのは `--init` の中でなので、順序を逆にすると「先週、確認できないまま消えた行」が1週遅れて表示される）
3. **`python3 tools/prev_rows.py movies --worklist` で前回分の棚卸しリストを取る**（省略禁止）。**先頭に出る「先週、確認できないまま消えた行」を最初に片付ける**
4. **公開予定カレンダー・配給会社の公開予定ページを対象期間の全月について確認し、新作ロードショーを取りこぼしなく拾う**（枠20回・ステップ1参照。**個別のシネコン検索だけに頼らない／シネコン店舗を1館ずつ当たらない**）
5. `python3 tools/roster.py theaters --list --urls` で名画座・単館（2列目が空欄の16件）を引き、**4列目のURLを直接開いて**「既存行の再確認」と「新規の発見」を同じ1回の調査で済ませる（検索の枠5回）。**上映スケジュールは `python3 tools/fetch_page.py <URL> --text` で取る**——日付と作品名の対応がタブ区切りで残る。収穫の記録は `append_rows.py` が自動で行う
6. 季節キーワードと横断サイトで、野外上映・ドライブインシアター・特別上映・映画祭を補完する（枠20回）
7. 各作品・上映について公式情報まで辿り、期間・目玉・料金を確定する（枠80回・**新規行のみ**。前回から続く行は前回の `official_url` に直行し、**変わりうる項目だけ**を確認して残りは `_carry` で持ち越す）。`theater` 列は上映形態ごとの書き方（新作はチェーン名、それ以外は具体的な会場名）に従う。**必須列が揃った行はそこで打ち切る**。**上映劇場を特定できない単館作品は、1回調べて分からなければ落とす**
8. **`python3 tools/purge_ended.py movies` で、終了日を過ぎた行を先に機械的に取り除く**（検索は使わない。消した行には `expired` の処分が自動で付く。`end_date` が未定の新作は対象外）
9. **`python3 tools/prev_rows.py movies --dispose` で、残った消えた行（8で片付いた分を除く）1件ずつに理由を記録する**
10. `python3 tools/roster.py theaters --gc` で名簿を整理する
11. `python3 tools/diff_data.py movies` と `python3 tools/validate_data.py` を実行し、どちらも**終了コード0**であることを確認する（`diff_data.py` は**収穫が0件でも落ちる**）
12. `python3 tools/report_stats.py movies` で充足率と分布を出す
13. 最後に、以下の要点だけを簡潔に出力する（あいさつや前置き、次の提案などの会話的な文章は付けない）

- 件数・都県別内訳・上映形態別内訳・ジャンル別内訳（`report_stats.py` の出力をそのまま使う）
- **中核列の充足率と前回比**（とくに前売りの `onsale_label` / `onsale_end`。落ちた列があれば理由も）
- **前回からの変化**（`diff_data.py` の出力をそのまま使う。記憶で書かない）
  - 新規公開／**上映延長・アンコール上映**／上映終了・公開延期
  - **`purge_ended.py` が自動削除した件数（`expired`）**（多いなら、tier A の再確認が追いついていない兆候として書く）
  - **`notfound` として残した件数**（0でないなら、その一覧も）
- 名簿の変化（追加した劇場／`retired` にした劇場／`--gc` の結果）
- **工程別の消費と、予算切れで打ち切った工程**（`budget.py --report --verbose` の出力をそのまま貼る。打ち切りが無ければ「なし」と書く）

- **上映劇場を特定できずに落とした作品の件数**（「新作は全件」の線引きで落ちた分）
