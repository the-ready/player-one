# イベントボード

関東エリアのイベント・映画・ライブ情報を単一のスキーマに正規化して1画面に並べ、横断的に検索・絞り込みできる静的ダッシュボード。予約導線は各イベント・作品・公演の公式サイト・予約サイトへ送客する。「イベント」「映画」「ライブ・フェス」の3タブがあり、**絞り込みUIも機能もタブ間で共通**（検索条件だけはタブごとに独立して保持される）。

いま何で絞っているかは常に画面上に出ていて1タップで外せる。絞り込みの状態はURLに載るので、絞り込んだ結果をそのまま人に渡せる。

`index.html` をルートに置いているのは、Pages がリポジトリのルートをそのまま配信する設定（`upload-pages-artifact` の `path: .`）のため。**ビルド工程・パッケージ依存はない**（`<script type="module">` で読むだけ）。

**書き換え頻度でフォルダを分けている。** 週次で差し替わるのは `data/` だけ、ほぼ変わらないのが `assets/`、という対応にすることで、更新作業がどこを触るのかを構成から読めるようにした。

外部依存は **Google Fonts と OpenStreetMap のタイルだけ**。どちらも読めなくても一覧の表示と絞り込みは成立する。CSVパーサは自前（`assets/js/csv.js`）、Leaflet は同梱にしてある。

### タブに機能を足すとき

3タブの描画・絞り込み・並べ替え・会場ピッカーはすべて共通の1本を通る。タブごとの違いは [`assets/js/config.js`](assets/js/config.js) の `TABS` 宣言だけが持つ。**新しい絞り込み軸を足すときも、原則としてこのファイルの宣言を編集するだけで3タブに行き渡る。**

**なぜそう作ってあるのか**は [`docs/DESIGN.md`](docs/DESIGN.md) に、判断の背景とセットで書いてある。仕様を変える前に読むこと。

## 探し方

- **検索窓** … 全角/半角、ひらがな/カタカナの違いを吸収する（`ｚｅｐｐ` で `Zepp`、`ずーらしあ` で `ズーラシア`）。スペース区切りは AND（`横浜 ロック`）。カテゴリ名でも引ける（`アート`）。漢字の読みで引きたい場合は CSV の `kana` 列に読みを入れる。一致箇所はハイライトされる
- **日程** … `今日` `今週末` `1週間` `今月` `3ヶ月` のプリセットとカレンダー。カレンダーは Tab 1回で入り、矢印キーで日を移動できる
- **エリア** … 現在地から近い順／地図で範囲をえらぶ／会場でしぼる／都県。後ろ3つは排他
- **絞り込み** … カテゴリ・ジャンル・開催状況などのチップ。**選択肢ごとに件数が出て、0件の選択肢は押せない**
- **適用中の絞り込み** … いま効いている条件は操作バーに並び、1タップで外せる。「すべての絞り込みを解除」は条件が1つでもあれば常に見える
- **URL** … 絞り込みの状態はURLに載る。そのまま人に渡せるし、ブックマークもできる。ブラウザの「戻る」で1つ前の絞り込みに戻る
- **行きたい／共有／カレンダー** … 各カードのアイコンから。「行きたい」はこの端末の中だけに保存され（ログイン不要・外部送信なし）、「絞り込み」から「お気に入りだけ」で呼び出せる。カレンダーは押すと「端末のカレンダー（.ics）」か「Googleカレンダー」を選べる
- **更新** … 本体に新しい版が出たら、確認を挟まず自動で入れ替える。絞り込みの状態はURLに載っているので、読み直しても見ていた条件はそのまま戻る

## 地図で範囲をしぼる

「エリア」→「地図で範囲をえらぶ」で地図シートが開く。画面中央のピンが検索の中心、その周りの円が検索範囲で、地図をドラッグすると中心が動き、ピンチや ＋ − で円が覆う実距離が変わる。円の中にあるイベント（映画タブでは映画）だけが検索結果になる。

- 円は画面上では常に同じ大きさ（表示領域の短辺 × `RING_RATIO`）で、ズームすると「円が覆う実距離」のほうが変わる。半径は円の縁までの東西方向の距離として算出する。
- 地図の範囲（`state.mapArea`）と県チップ（`state.pref`）は排他。どちらも「場所の絞り込み」であり、AND で重ねると必ず0件になる組み合わせを作れてしまうため。
- 地図は追加の絞り込み手段であり必須ではない。Leaflet は同梱してあり（`assets/vendor/leaflet/`）、初回にシートを開いたときだけ遅延読み込みする。読み込みに失敗しても他の機能は動く。キーワード検索と県チップだけでも同じ絞り込みができる。
- 絞り込み判定はすべてブラウザ内で完結する（座標の外部送信はない）。座標が未登録のイベントは、地図でしぼりこむと対象外になる。
- 地図タイルは OpenStreetMap（&copy; OpenStreetMap contributors）。API キーも課金アカウントも不要。

## ローカルでの確認

`index.html` は `data/` 配下の CSV を `fetch` で取得するため、`file://` で直接開くと動作しない。HTTP 経由で開くこと。

```sh
python3 -m http.server 8000
# → http://localhost:8000/
```

CSVを差し替えたら、検証を通してから確認すること。

```sh
python3 tools/validate_data.py
```

列のずれ・日付の書式・未知のカテゴリキー・座標の取り違え・割引率の不整合などを見る。表示側は欠損や未知の値でも落ちない設計だが、**落ちたことが誰にも伝わらない**のが問題なので、先に気づけるようにしてある。ERROR が出た状態のデータは公開しない。

画面側を大きく触ったときは、スモークテストも通す（Playwright が要る）。

```sh
npm i -D playwright && npx playwright install chromium
node tools/smoke_test.mjs          # BASE=... で公開URLにも当てられる
```

3タブが描画されるか、絞り込みが件数を変えるか、URLが状態を持つか、キーボードでカレンダーを操作できるか、コンソールエラーが出ていないかを見る。細かい見た目までは見ない——「壊れているのに気づかないまま公開する」ことだけを防ぐためのもの。

どちらもCIには組み込んでいない（デプロイの挙動を変えないため）。手元とスキルの品質チェック工程から実行する。

## データの更新

`data/events.csv` を差し替えるだけでよい。列は以下の45列を固定（順序・列名ともに変更しない）。空欄でよい列は多いが、**列そのものを省いてはいけない**。

```
id,title,kana,cats,area,venue,venue_url,pref,start_date,end_date,date,dates,open_time,start_time,end_time,date_note,backup_date,status,rank,series_id,announced_date,is_additional,onsale_label,onsale_start,onsale_start_time,onsale_end,onsale_end_time,limited_sale,price,price_official,price_best,discount_pct,best_source,coupon_note,price_checked,price_condition,source,url,official_url,lat,lng,desc,note,parking,nearest_station
```

**日程の列は「機械が読める事実」だけを書く。** 画面に出る日付の文字列（`2026.9.5(土) 開場16:00／開演18:00`）も、`開催中` `まもなく開催` といった開催状況も、表示のたびに `start_date`／`end_date`／`dates`／`open_time`／`start_time`／`end_time`／`date_note` と**そのとき の日本時間**から組み立てられる。つまり **CSVを差し替えなくても、日付をまたげば表示が追いつく**。`date` 列は「10月中旬〜下旬（見頃予想）」のようにISOの日付へ落とせない日程だけを書く逃げ道で、通常は空欄。**ただし月・季節までは読み取れる場合は `start_date`/`end_date` にその月・季節をまるごと設定すること**（10月なら`2026-10-01`〜`2026-10-31`）——空欄のままだと絞り込みが「無期限」として扱い、無関係な日で絞っても表示されてしまう（第3.9.6節）。`status` / `rank` も、日付を1つも持たない行以外は空欄でよい（書いても無視される）。単日開催では `end_date` に `start_date` と同じ日を入れること——空欄は「終了日が未定」という別の意味になる。`dates`（飛び日程）を書いた行では、開催しない日は「本日は休み」と表示され、日程の絞り込みからも外れる。`backup_date`（予備日）は**会期に含めず**、カードの「くわしく」の中に出す——本開催で終われば使われない日なので、`end_date` を1日延ばすと「まだやっている」と嘘をつくことになる。ただし予備日の当日だけは「本日予備日」というバッジが出る（本開催が流れていればその日にやるので、「終了」と出すのは早すぎるため）。詳しくは `docs/DESIGN.md` 第3.9節。

`kana` は読み検索用（`隅田川花火大会` → `すみだがわはなびたいかい`）。`series_id` は巡回展をまとめるキー。`onsale_*` は事前予約・抽選・整理券の受付期間で、当日ふらっと行けるイベントは空欄でよい。`price_condition` は割引の適用条件で、**条件付きの割引を書いたら必須**（条件を伏せた安い価格は、値段を出さないより有害になる）。`parking` は駐車場情報（例：`あり（有料・120台）`）、`nearest_station` は最寄り駅と徒歩時間（例：`上野駅（徒歩10分）`）で、どちらも「くわしく」の中に表示される。会場公式サイトで確認できなければ空欄でよい（憶測で埋めない）。

価格は確認日時点のスナップショットであり、`price_checked` に確認日を記録する。リアルタイムの価格追従は行わない。

フッターの「◯年◯月◯日時点」は `price_checked` の最大値（＝価格を調査した日）から自動で表示する。カレンダーの初期表示・期間プリセット・並べ替えの起点・開催状況の判定に使う「本日」は、閲覧するたびに日本時間の現在日から採り直す。**CSVを差し替えるときに `index.html` 側で書き換える日付はない。**

### ヘッダーの「最終更新日」

**表示中のタブが読んでいるCSVの更新日**を出す。イベント・映画・ライブは別々のスキルが別々のタイミングで更新するので、タブを切り替えると日付も切り替わる。

出どころは次の優先順。どちらも「そのファイルがいつ更新されたか」で、測り方が違うだけ。

1. `data/updated.json` … 各CSVの**中身**が最後に変わったコミットの日時。**デプロイ時に git の履歴から生成される**（`.github/workflows/pages.yml`）。コミットはしない（`.gitignore` 済み）
2. CSVレスポンスの `Last-Modified` … ローカルのWebサーバーではこちらが正しい
3. どちらも取れなければ `–`

`Last-Modified` だけに頼らないのは、`actions/checkout` が全ファイルのタイムスタンプをチェックアウト時刻にそろえてしまい、**GitHub Pages 上では3つのCSVが同じ「デプロイ日時」になってタブごとの差が消える**ため。

git 側は `git log --follow -M` で名前の変更を辿り、**中身が変わっていない移動（`R100`）は数えない**。単純な `git log -1 -- <path>` だと、`data/` へのフォルダ再編でファイルを移動しただけのコミットを「データの更新」と誤認する（実際に踏んだ）。

表示は**日本時間の日付に固定**する。閲覧者のタイムゾーンで換算すると、同じデータを見ている人どうしで表示が1日ずれるため。

CSVの中身の日付（`price_checked` 等）にはフォールバックしない——「差し替えた日」と「調査した日」が混ざると、画面の日付が何を指すのか分からなくなるので。

列が空でもページは壊れない設計にしてある（`source` が空ならボタンは「予約ページを開く」、`price` が空なら価格行を出さない、`official_url` が `url` と同じなら公式リンクを重複表示しない、`cats`/`status` に未知の値が来ても既定の見た目にフォールバックする）。

`data/events.csv` の更新は `/kanto-event-collector` スキルが週次で担当する。

> **書き出し先に注意**: `.claude/skills/` が正本だが、`~/.claude/skills/` に置いたコピーは自動同期されない。CSV の置き場所を変えたら両方を更新すること。ルート直下に `events.csv` が書かれても、ダッシュボードは `data/events.csv` しか読まない（取得先を1つに保つため、別パスへのフォールバックは意図的に持たせていない）。

収集は**差分方式**で動く。毎回ゼロから調べ直すのではなく、前回の結果を棚卸しして「まだやっているか・会期が延びたか・中止になっていないか」を確認しつつ、同じ調査のついでに新規を拾う。前回あって今回無い行には理由の記録が要り、説明のない消滅は `tools/diff_data.py` が検出して落とす。考え方と手順は `docs/COLLECTION-PROTOCOL.md` にまとめてある。

## 映画コーナー

新作公開・名画座のリバイバル上映・野外上映やドライブインシアターなどの突発的な上映・爆音上映やオールナイトなどの特別上映・映画祭を1つの一覧にまとめたタブ。カードのつくりはイベント・ライブと同一で、画像を持たず、左上のカテゴリバッジとタイポグラフィだけで識別性を作る。

検索・絞り込みはイベントタブと共通のUI部品を使う。日程カレンダーは完全に同じコンポーネントで、場所の絞り込み（都県チップ・地図の範囲検索・現在地から近い順）もイベントと同じ仕組みをそのまま使っている。劇場・上映会場の緯度経度さえ`data/movies.csv`に入れておけば、常設のシネコンでも、ドライブインシアターのような臨時の屋外上映会場でも同じように検索対象になる。カテゴリの絞り込みだけは映画向けに「ジャンル」「上映形態」の2種類を持つ。

### 画像を扱わない

3タブとも、写真・ポスター・キービジュアル等の画像を一切扱わない。`data/movies.csv` に画像の列は無く、画像ファイルの複製・保存も、URLを参照しての表示も行わない。

権利者が出しているのは自社サイトへ掲載するための許諾であって、第三者サイトへの再掲載や画像への直リンクの許諾ではないためである。「ファイルを複製せずURL参照するだけ」という論理は著作権侵害の局面では概ね通るが、サイトの利用規約違反と著作者人格権（氏名表示権）の問題は何も片付かない（`docs/DESIGN.md` 第7.1節）。

このルールは `tools/validate_data.py` が ERROR で落とす（`poster_url` / `poster_source` の列が存在した時点で失格）。散文のお願いは安いほうの経路へ流れるので、仕組みで固定してある。

### `data/movies.csv` の列（44列固定）

```
id,title,kana,genre,screening_type,area,theater,theater_url,pref,release_date,end_date,date,dates,open_time,start_time,end_time,date_note,backup_date,status,rank,series_id,announced_date,is_additional,onsale_label,onsale_start,onsale_start_time,onsale_end,onsale_end_time,limited_sale,price,price_official,price_best,discount_pct,best_source,coupon_note,price_checked,price_condition,source,url,official_url,lat,lng,desc,note
```

`onsale_*` は前売り券（ムビチケ等）の販売期間。`series_id` は特集上映・映画祭のプログラムをまとめるキー。`price_official` 〜 `price_condition` は料金の比較レイヤーで、**映画の割引はほとんどが条件付き**（会員限定・特定曜日・時間帯）なので `price_condition` は必須扱い。条件を特定できない割引は書かずに落とす。

`genre` は `anime` `jp-live` `foreign` `doc` `fam` `tokusatsu` `music` の複数選択可（`|`区切り）。`screening_type` は `new`(新作公開) `revival`(名画座・リバイバル) `outdoor`(野外上映・ドライブイン) `special`(特別上映) `festival`(映画祭)。開催状況（`本日が最終上映` `まもなく公開` `上映中` `前売り券発売中` `上映終了`）は日付から自動で決まる。

`data/movies.csv` の更新は `/kanto-movie-collector` スキルが週次で担当する（書き出し先の注意は `events.csv` と同じ）。

### 上映会社（`theater`列）の書き方とチェーン店舗マップ

新作ロードショー（`screening_type`に`new`を含む行）は、特定の1館名ではなく**上映しているシネコンチェーン名**を`theater`列に書く（例：`TOHOシネマズ`）。複数チェーンで同時公開されている場合は`TOHOシネマズ|109シネマズ`のように`|`区切りで複数書ける。名画座のリバイバル上映・野外上映/ドライブインシアター・特別上映・映画祭は、引き続き具体的な劇場・会場名を書く（そこでしか観られない一回性の企画のため）。**例外として、`new`でも本当に1館（単館系ミニシアター限定公開など）でしか上映されないと確認できた場合は、その劇場名を書いてよい**（無理にチェーン名へ寄せない。詳細は`.claude/skills/kanto-movie-collector/SKILL.md`の「`theater`列の書き方」を参照）。

ダッシュボードは、`theater`列の値が`data/theaters.csv`の`chain`列に実在する値と一致する場合だけ、そのチェーン名をリンクとして表示する。クリックすると、そのチェーンの関東の店舗が地図にピン表示されるモーダルが開く（`data/theaters.csv`の`chain,name,pref,area,lat,lng,url`を参照。このファイルにはさらに名簿の保守用の列が末尾に付いていて全12列だが、表示側は列名で引くので影響しない）。一致しない場合（名画座・野外上映などの具体的な会場名）は「会場名／エリア」のテキスト表示になり、その行に`theater_url`があれば会場名がその劇場サイトへのリンクになる（会場が1つの行のみ。`|`で複数会場を書いた行は、どの会場のURLか特定できないためリンクにしない）。

`data/theaters.csv`は`data/movies.csv`ほど頻繁には変わらない準静的なマスターデータで、**週次の収集タスクが`tools/roster.py`経由で育てる**（新規出店・閉館・長期休館の反映、収穫のない先の整理）。名簿は放っておけば必ず腐るため、手動更新にせず収集タスク自身に保守させている（`docs/COLLECTION-PROTOCOL.md`第7章）。**自動更新されるのは名簿というデータだけで、収集ルール（SKILL.mdの散文）は書き換えさせない。**

## ライブ・フェスコーナー

これから開催されるライブ・コンサート・音楽フェスを1つの一覧にまとめたタブ。カードのつくりはイベント・映画と同一で、複数出演（フェス・共演）の公演ではタイトル直下に出演者名をテキストで並べる。

検索・絞り込みはイベント・映画と共通のUI部品を使う。ライブ固有の軸は「ジャンル」「公演形態」の2つで、それ以外（受付状態・締切カウントダウン・会場ピッカー・新着順・シリーズの他会場）は**もともとここで作られ、いまは3タブ共通になっている**。

### もとはライブ専用だった機能（現在は3タブ共通）

| 機能                           | 内容                                                                                                                                                                                                                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **受付情報をカード表面に表示** | 発売日時・締切・限定枠を「くわしく」の中ではなくカードの表に出す。状態は「発売前／受付中／受付終了」の3つを色で区別。**時刻まで含めて判定する**（先着順の販売では `10:00` を知らないと並べないため）。イベントでは事前予約・抽選・整理券、映画では前売り券の販売期間に対応する |
| **締切カウントダウン**         | `onsale_end` が7日以内なら「締切 ◯月◯日（あと◯日）」を警告色で。**公演日が先でも受付が先に締まる**ため                                                                                                                                                                         |
| **限定・追加販売**             | 見切れ席・追加席・公式リセール・当日券など、その行にだけ出る枠を表示                                                                                                                                                                                                           |
| **追加公演／NEWバッジ**        | `is_additional` が立つ行にバッジ（イベントは「追加開催」、映画は「上映延長」）、`announced_date` が7日以内の行に「NEW」                                                                                                                                                        |
| **会場でしぼる**               | エリアのポップアップから会場を選べる。候補は実際に予定がある会場だけを件数順に表示。会場・都県・地図の範囲は三者排他。映画では `theaters.csv` を使った劇場ピッカーになる                                                                                                       |
| **会場シート**                 | カードの会場名を押すと、地図・会場種別・収容人数・公式サイトに加えて**その会場のこれからの予定**（3タブ横断）が出る。映画のチェーン店舗マップもこのシートに統合した                                                                                                            |
| **シリーズの他の会場**         | 「くわしく」の中に、同じシリーズの他会場を**それぞれの受付状態・限定枠つき**で並べる。「東京は完売だが横浜はこれから発売」が1枚で分かる。ライブ＝ツアー（`tour_id`）、イベント＝巡回展、映画＝特集上映（`series_id`）                                                          |
| **新着順**                     | 日程ポップアップから並び順を「発表が新しい順」に切り替えられる                                                                                                                                                                                                                 |

### 出演者名をテキストで置く

画像は3タブとも扱わない（「映画コーナー」の「画像を扱わない」を参照）。ライブでは代わりに、複数出演（フェス・共演）の公演でタイトル直下に出演者名を並べる。文字は事実情報なので権利上の制約がなく、フェスでは小さく表示された画像より情報量が多い（画像からは出演者を読み取れない）。したがって `artists` 列の充実が、そのままカードの情報量になる。

### 二次流通・転売サイトへはリンクしない

`url` に入るのは公式サイトと正規プレイガイド（チケットぴあ／イープラス／ローソンチケット／楽天チケット／ticket board／LivePocket／ZAIKO／teket 等）のみ。完売公演も掲載するが、`onsale_label` を `SOLD OUT` にして取れるように見せない（公式リセールや当日券の可能性があり、「何をやっているか」自体が情報のため）。

### `data/lives.csv` の列（42列固定）

```
id,tour_id,title,kana,artists,genre,live_type,area,venue,venue_url,pref,start_date,end_date,date,dates,open_time,start_time,end_time,date_note,backup_date,status,rank,announced_date,is_additional,onsale_label,onsale_start,onsale_start_time,onsale_end,onsale_end_time,limited_sale,price,source,url,official_url,lat,lng,desc,note,parking,nearest_station,apple_music_url,lineup_id
```

**このタブは価格比較レイヤーを持たない。** `price_official` / `price_best` / `discount_pct` の列は存在しない。チケットは定価固定で、プレイガイドを横断しても値段が変わらないため。

`parking` / `nearest_station` はイベントと同じ意味の列で、「くわしく」の中に表示される。`apple_music_url` は**その公演のメインアーティスト1組**（フェス・共演では `artists` の最初の1組）の Apple Music アーティストページへのリンク。Apple のアーティストページURLは `https://music.apple.com/{ストアフロント}/artist/{スラッグ}/{アーティストID}` という決まった形を取り、iTunes Search API（`https://itunes.apple.com/search?entity=musicArtist`）で名前から `artistLinkUrl` を機械的に引ける。同姓同名の別アーティストと取り違えるおそれがあるため、確信が持てない場合は空欄にする。

### フェスの日割りラインナップ（`data/lineups.csv`）

`artists` 列はフェスでも主要8組までしか持たない（カードのタイトル直下に出る行の材料で、200組を1セルに入れると表示もCSVも壊れる）。**全出演者は `data/lineups.csv` に「1行＝そのフェスの、その日の、そのアーティスト」で持つ。**

```
lineup_id,date,stage,artist,is_headliner,apple_music_url,note
```

`lives.csv` の `lineup_id` と同じ値の行が、その公演のラインナップになる。カードには「全◯組の日程を見る」ボタンが出て、日タブ → ステージ → 出演者のシートが開く。`date` と `stage` は空欄でよい（日割り・ステージ割りの発表前は実際にある）。`apple_music_url` は**手で書かない**。ラインナップを書き終えたあとに `tools/fill_apple_music.py` を実行すると、iTunes Search API から一括で埋まる。絞り込めなかった名前は空欄のまま残り、表示側が名前から Apple Music の検索URLを組み立てる。

このファイルは本体データと同時に読み込まれ、**全出演者名が検索の索引に入る**。`artists` の8組に入っていないアーティスト名でも、そのフェスが検索で見つかる。詳細は設計書 第12.12節。

`genre` は `rock` `pop` `idol` `kpop` `hiphop` `dance` `jazz` `classical` `anime` `other` の複数選択可（`|`区切り）。`live_type` は `fes`(音楽フェス) `oneman`(ワンマン・ツアー) `event`(対バン・イベント) `classic`(クラシック公演) `free`(入場無料) から1つ。開催状況（`本日開催` `まもなく開催` `開催中` `公演予定` `終了`）は日付から自動で決まる。

**ツアーは1公演＝1行**にする（`venue` に複数会場を書かない）。同じツアーの行には共通の `tour_id` を振る。同一会場での連日公演と複数日開催のフェスだけ、`start_date`/`end_date` で1行にまとめてよい。

### 会場（`venue`列）とライブ会場マスター

`venue` は `data/venues.csv` の `venue` 列と**完全一致**させる。一致した場合だけ会場名がボタンになり、会場モーダル（地図・収容人数・その会場の公演一覧）が開く。一致しない臨時会場は、`venue_url` があれば会場名がそのサイトへのリンクになる。

`data/venues.csv` は `venue,kind,pref,area,capacity,lat,lng,url`（＋名簿の保守用の列で全14列）。`kind` は `dome` `arena` `hall` `livehouse` `outdoor`。`data/theaters.csv` と同じく**準静的なマスター**だが、開館・閉館・改称・長期休館は週次の収集タスクが `tools/roster.py` 経由で反映する。

`lives.csv` の `lat`/`lng` は、会場がマスターに載っていれば空欄でよい（読み込み後に補われる）。臨時の野外会場など、マスターに無い会場のときだけ書く。

`data/lives.csv` の更新は `/kanto-live-collector` スキルが週次で担当する。

**3つの収集スキルはいずれもリポジトリ内の [`.claude/skills/`](.claude/skills/) が正本**で、`~/.claude/skills/` にはそのコピーを置く。リポジトリ外に置くと、CSVの列や構成を変えてもスキル側へ伝わらないためである。CSVの列を変えたら、`.claude/skills/` の3つと `~/.claude/skills/` の両方を更新すること。
